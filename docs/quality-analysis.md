# 动画区画质 / 帧率分析

## 当前链路

| 环节 | 数值 |
|---|---|
| 手机屏幕 | 1080×1920，60Hz，DPR 2.75 |
| 动画区（上 2/5） | 1080×768 物理像素 |
| 视频元素 | 1280×720 物理像素（左右各裁 100px） |
| 角色实际占屏 | 约 404×532 物理像素 |
| 原始素材 | **640×360，24fps**，角色约 200×330 |
| 浅色 / 黑灰成片 | 1920×1080，H.264，CRF18，24fps |
| 解码 | WebView / MediaCodec 硬件解码 |

## Debian 转码实测（Ryzen 7 5800H，16 线程）

| 目标 | 单段 10s 耗时 | 全量 106 段×2 主题 |
|---|---|---|
| 1920×1080 24fps | 约 2.1s | **5m54s**，518MB |
| 1280×720 60fps（minterpolate） | 约 **1m45s** | 约 3 小时+ |
| 1920×1080 60fps（minterpolate） | >3 分钟（未跑完） | 5 小时以上 |

## 结论

- **1080p 24fps 重转已做**：对 640 源做 3× Lanczos 到 1080p，再缩到 720 显示，等于 1.5× 超采样；边缘更干净，但**不会增加真实细节**（源只有 640）。
- **帧率不会因为转码变高**：源是 24fps。`minterpolate` 可以补到 60fps，但单段成本 1m45s–3min，全量 3–5 小时，而且 2D 平涂角色容易出现肢体扭曲/鬼影；不建议全量。
- 想真正提升清晰度只有两条路：
  1. 拿到更高分辨率的原始动画（作者当前只发 640）；
  2. 用 Real-ESRGAN 之类的 AI 超分（Debian Vega 可跑，但 106 段×240 帧成本高，先做核心 13 段更现实）。
- 想提升流畅度：
  - 只对核心 13 段（待机/思考/工作/点击）做 60fps 插帧，成本约 20–40 分钟；
  - 或保持 24fps——这是动画本身的帧率，非播放器掉帧。

## 当前选择

已切换到 1080p24 成片（`assets-light/`、`assets-dark/`，720p 备份在 `assets-light-720/`、`assets-dark-720/`）。角色显示尺寸不变，边缘更干净。

回滚：

```bash
mv assets-light assets-light-1080 && mv assets-light-720 assets-light
mv assets-dark assets-dark-1080 && mv assets-dark-720 assets-dark
systemctl restart dsh-pet-screen
```
